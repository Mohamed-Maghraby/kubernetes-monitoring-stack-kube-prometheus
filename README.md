# Kubernetes Monitoring Stack with kube-prometheus-stack Using Helm.

## Project Overview

This project documents the deployment of a complete Kubernetes monitoring stack on a kubeadm-based Kubernetes cluster using the `kube-prometheus-stack` Helm chart.

The monitoring stack includes Prometheus, Grafana, Alertmanager, kube-state-metrics, Prometheus Operator, Node Exporter, and admission webhooks. The goal of the Project is to install the stack, verify that all components are running, access Grafana and Prometheus, inspect monitoring targets, and troubleshoot common kubeadm monitoring issues.

No real public IP addresses, private IP addresses, tokens, keys, or kubeconfig files are included in this repository.

## Stack Components

The Helm chart deployed the following monitoring components:

| Component           | Purpose                                                                                        |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| Prometheus Server   | Collects and stores metrics from Kubernetes components and workloads.                          |
| Grafana             | Provides dashboards and visualization for Prometheus metrics.                                  |
| Alertmanager        | Handles alerts generated by Prometheus rules.                                                  |
| kube-state-metrics  | Exposes Kubernetes object state as metrics.                                                    |
| Prometheus Operator | Manages Prometheus, Alertmanager, ServiceMonitor, PodMonitor, and PrometheusRule resources.    |
| Node Exporter       | Collects node-level metrics such as CPU, memory, filesystem, and network usage.                |
| Admission Webhooks  | Validates Prometheus Operator custom resources before they are accepted by the Kubernetes API. |

## 1: Configure Helm

Add the Prometheus Community Helm repository:

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
```

Update the Helm repository index:

```bash
helm repo update
```

Search for the chart:

```bash
helm search repo prometheus-community/kube-prometheus-stack
```

List available versions:

```bash
helm search repo prometheus-community/kube-prometheus-stack --versions | head
```

## 3: Deploy kube-prometheus-stack

Install the chart:

```bash
helm upgrade --install monitoring-stack prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --wait \
  --timeout 15m
```

Verify the Helm release:

```bash
helm list -n monitoring
```

Expected status:

```text
deployed
```

## 5: Access Grafana

Port-forward the Grafana service:

```bash
kubectl -n monitoring port-forward svc/monitoring-stack-grafana 3000:80
```

Access Grafana locally:

```text
http://localhost:3000
```

For an EC2-based cluster, SSH tunneling can be used from the local machine:

```bash
ssh -i <SSH_KEY_FILE> -L 3000:127.0.0.1:3000 <USER>@<MASTER_PUBLIC_IP>
```

Retrieve the Grafana admin username:

```bash
kubectl get secret -n monitoring monitoring-stack-grafana \
  -o jsonpath="{.data.admin-user}" | base64 -d; echo
```

Retrieve the Grafana admin password:

```bash
kubectl get secret -n monitoring monitoring-stack-grafana \
  -o jsonpath="{.data.admin-password}" | base64 -d; echo
```

After login, Prometheus was verified as the default data source.

## Troubleshooting Issues Faced

### Issue 1: Grafana access on EC2

Problem:

Opening this URL from the local browser did not work directly:

```text
http://localhost:3000
```

Reason:

The `localhost` address referred to the EC2 instance, not the local machine.

Fix:

Use SSH tunneling:

```bash
ssh -i <SSH_KEY_FILE> -L 3000:127.0.0.1:3000 <USER>@<MASTER_PUBLIC_IP>
```

Then open locally:

```text
http://localhost:3000
```

---

### Issue 2: Prometheus targets were DOWN for kube-controller-manager

Prometheus error:

```text
connect: connection refused
```

Reason:

The kube-controller-manager metrics endpoint was listening only on localhost:

```text
127.0.0.1:10257
```

Fix:

Edit the kube-controller-manager static pod manifest:

```bash
sudo sed -i 's/--bind-address=127.0.0.1/--bind-address=0.0.0.0/' \
/etc/kubernetes/manifests/kube-controller-manager.yaml
```

Restart kubelet:

```bash
sudo systemctl restart kubelet
```

Verify:

```bash
sudo ss -lntp | grep 10257
```

Expected:

```text
0.0.0.0:10257
```

---

### Issue 3: Prometheus target was DOWN for kube-scheduler

Prometheus error:

```text

```

Reason:

The kube-scheduler metrics endpoint was listening only on localhost:


Force static pod recreation if needed:

```bash
sudo mv /etc/kubernetes/manifests/kube-scheduler.yaml /tmp/kube-scheduler.yaml.fixed
sudo mv /tmp/kube-scheduler.yaml.fixed /etc/kubernetes/manifests/kube-scheduler.yaml
```

Verify:

```bash
sudo ss -lntp | grep 10259
```

Expected:

```text
0.0.0.0:10259
```

---

### Issue 4: Prometheus target was DOWN for etcd

Prometheus error:

```text
connect: connection refused
```

Reason:

The etcd metrics endpoint was listening only on localhost:

```text
127.0.0.1:2381
```

Fix:

Edit the etcd static pod manifest:

```bash
sudo sed -i 's|--listen-metrics-urls=http://127.0.0.1:2381|--listen-metrics-urls=http://0.0.0.0:2381|' \
/etc/kubernetes/manifests/etcd.yaml
```

Force etcd static pod recreation if needed:

```bash
sudo mv /etc/kubernetes/manifests/etcd.yaml /tmp/etcd.yaml.fixed
sudo mv /tmp/etcd.yaml.fixed /etc/kubernetes/manifests/etcd.yaml
```

Verify:

```bash
sudo ss -lntp | grep 2381
```

Expected:

```text
0.0.0.0:2381
```

## 10: Grafana Dashboard Work

Grafana was used to verify and visualize the collected metrics.

Recommended dashboard panels:

| Panel                     | PromQL                                                                              |
| ------------------------- | ----------------------------------------------------------------------------------- |
| Target Health by Job      | `sum by (job) (up)`                                                                 |
| Node CPU Usage            | `100 * (1 - avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])))`      |
| Node Memory Usage         | `100 * (1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes))`         |
| Running Pods by Namespace | `sum by (namespace) (kube_pod_status_phase{phase="Running"})`                       |
| Pod Restarts              | `sum by (namespace, pod) (increase(kube_pod_container_status_restarts_total[15m]))` |
| Node Ready Status         | `kube_node_status_condition{condition="Ready",status="true"}`                       |

## Security Notes

The following items are intentionally excluded from this repository:

```text
Real EC2 public IPs
Real private node IPs
SSH private keys
Kubernetes admin.conf
kubeconfig files
Tokens
Secrets
Passwords
Cloud credentials
```

Metrics ports such as `10257`, `10259`, `10249`, and `2381` should not be exposed publicly through the EC2 Security Group. They should only be reachable inside the private cluster network.
